# Cloudflare Installation and Configuration Guide

[Cloudflare](https://www.cloudflare.com/) is a popular content delivery network
(CDN) and DDoS mitigation service that provides various features to enhance the
security and performance of websites. In this guide, we will go through the
steps to set up Cloudflare for your website.

[Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-apps/)
is a service provided by Cloudflare that allows you to securely connect your
server to Cloudflare's network without exposing your server's IP address and
ports. This can also help protect your server from DDoS attacks and other
malicious activities.

## 1. Prerequisites

Before we begin, make sure you have the following:

- A domain name that you own and can manage DNS settings for.
- A server or hosting provider where your website is hosted.
- Access to your server's terminal or command line interface.
- A Cloudflare account. You can sign up for a free account at
  [Cloudflare's website](https://www.cloudflare.com/).
- The Cloudflare Tunnel client installed on your server. You can follow the
  installation instructions for your operating system in the
  [Cloudflare Tunnel documentation](https://developers.cloudflare.com/cloudflare-one/connections/connect-apps/install-and-setup/installation/).

## 2. Install `cloudflared`

Install `cloudflared` on a host that can reach the application over the local
network. A dedicated unprivileged container is preferred for a public-facing
application. Do not install it on the Proxmox host unless you have a specific
reason to do so.

For Debian or Ubuntu, follow the
[Cloudflare installation documentation](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)
for the package appropriate to your distribution.

After installation, confirm that the command is available:

```bash
cloudflared --version
```

The tunnel only needs outbound access to Cloudflare. You do not need to open
inbound ports 80 or 443 on your router for a tunnel.

## 3. Create a tunnel with a token

The simplest setup uses a tunnel token generated by the Cloudflare dashboard.
This avoids creating a local tunnel credential or manually maintaining an
`ingress` configuration file.

1. Open the [Cloudflare Zero Trust dashboard](https://one.dash.cloudflare.com/).
2. Go to **Networks** > **Tunnels** and select **Create a tunnel**.
3. Choose **Cloudflared**, enter a name such as `homelab`, and create the
   tunnel.
4. Select **Linux** and copy the installation command that includes the tunnel
   token.
5. Run that command on the host or dedicated container that can reach your
   application.

The command will resemble the following:

```bash
sudo cloudflared service install <TUNNEL_TOKEN>
sudo systemctl enable --now cloudflared
sudo systemctl status cloudflared
```

Use the exact command generated by Cloudflare. Do not paste the token into this
document, shell history that will be shared, source control, or support logs.
Treat the token like a password: anyone who has it may be able to run the
tunnel.

If you prefer to run `cloudflared` in Docker, use the token supplied by the
dashboard:

```bash
docker run -d --name cloudflared --restart unless-stopped \
  cloudflare/cloudflared:latest tunnel --no-autoupdate run \
  --token <TUNNEL_TOKEN>
```

## 4. Configure a public hostname

After the connector is running, return to the tunnel in the Cloudflare dashboard
and open **Public Hostname** or **Add a public hostname**.

1. Enter the subdomain and select the domain, such as `app.example.com`.
2. Choose the application protocol, usually **HTTP** or **HTTPS**.
3. Enter the private application address, such as `10.10.10.20:8080`.
4. Save the route.

Cloudflare creates the DNS record for the public hostname as part of this
process. Keep the application on a private address; do not point the tunnel at a
public address unnecessarily.

The hostname and origin service can be changed later from the dashboard without
reinstalling `cloudflared` or changing the token on the connector.

## 5. Secure the application

A tunnel encrypts the connection between `cloudflared` and Cloudflare, but it
does not automatically authenticate users to your application. Apply the
following controls:

- Expose only the hostnames and services that you intend to publish.
- Use HTTPS between `cloudflared` and the origin when the application supports
  it.
- Enable application authentication and multi-factor authentication.
- Add a Cloudflare Access application for private or administrative services.
- Keep Proxmox, SSH, databases, and other management interfaces private.
- Do not publish a service that is not intended to be reachable from the
  internet.
- Review application and Cloudflare Access audit logs regularly.

For services that should remain private, use NetBird or another private access
solution instead of publishing them through a public hostname.

## 6. Verify the tunnel

From the tunnel host, confirm that the origin application is reachable:

```bash
curl -I http://10.10.10.20:8080
```

From a separate network, open `https://app.example.com` and confirm that the
request reaches the intended application. Also verify that:

- The DNS record points to the tunnel and does not expose the origin IP.
- The tunnel is shown as **Healthy** in the Cloudflare dashboard.
- Requests to unknown hostnames receive a 404 response.
- Authentication is required where it is expected.
- The origin cannot be reached directly from the internet.

Monitor the service after rebooting the tunnel host:

```bash
systemctl is-enabled cloudflared
systemctl is-active cloudflared
journalctl -u cloudflared --no-pager -n 100
```

## 7. Troubleshooting

### The tunnel will not start

Check the configuration and credential path:

```bash
systemctl status cloudflared
journalctl -u cloudflared --no-pager -n 100
```

If the service does not start, rerun the exact token-based install command from
the Cloudflare dashboard. Confirm that the token was copied completely and that
the host can make outbound HTTPS connections.

### The hostname returns a 502 or 504

The tunnel is connected, but `cloudflared` cannot reach the origin. Check the
origin address and port from the tunnel host:

```bash
curl -v http://10.10.10.20:8080
ss -lntup
```

Confirm that the application is listening on the expected interface and that the
local firewall allows traffic from the tunnel host.

### DNS is not resolving

Confirm that the domain is active in Cloudflare and that the public hostname was
saved under the correct tunnel in the Cloudflare dashboard. DNS changes may take
time to appear, especially if a previous DNS record has a long TTL. Do not
create a second conflicting record for the same hostname.
